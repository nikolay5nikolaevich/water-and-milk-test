# Расчёт заказа поставщикам

Тестовое задание на вакансию начинающего разработчика: программа считает, сколько единиц каждого товара заказать. Оценивают правильность расчёта, понятность кода и запуск по README. На собеседовании автор объясняет логику и вносит **изменение условия** вживую, поэтому код должен оставаться маленьким и читаемым, а любое правило формулы — правиться в одном месте.

**Дизайн повторяет сайт заказчика** из соседней папки `../вода и молоко сайт` (его `DESIGN.md` §7 — палитра и типографика). Оттуда токены (`--milk`, `--ink`, `--yellow`, `--green-deep`), шрифты Comfortaa + Inter Tight, заголовок «капс + повёрнутая акцентная строка», пилюли-кнопки, ошибки текстом без красных рамок, а также `public/img/hero.webp` (их кадр «ассортимент»), логотип и favicon. Новые элементы строй из этих же паттернов; при сомнении сверяйся с их `src/styles.css`.

Стек задан пользователем: Vite + чистый JS (без фреймворков) для сайта и CLI, хостинг Vercel через GitHub; Python только для тестов и проверки входных данных. Интерфейс, README и сообщения об ошибках — на русском.

## Где что

- `src/calc.js` — **единственный источник истины** для формулы, разбора CSV и валидации. Сайт (`src/main.js`) и CLI (`cli.js`) только импортируют его.
- `tests/reference.py` — **независимый эталон** той же формулы на `Decimal`. Он намеренно не переиспользует JS: сверка двух реализаций и есть тест.
- `tests/test_orders.py` — вызывает `node cli.js --json` и сравнивает с эталоном (пример, граничные случаи, `invalid.csv`, 2000 случайных товаров).
- `data/products.csv` — пример из ТЗ; `data/invalid.csv` — по строке на каждый вид ошибки.
- Команды — в `package.json` (`calc`, `dev`, `build`, `test`).

## Правила, которых нет в коде

- **Изменение формулы = три правки вместе**: `calcOrder` в `src/calc.js`, `calc_order` в `tests/reference.py`, ожидаемые числа в `SampleFile` и пример вывода в `README.md`. Строка `explain()` тоже описывает формулу — держи её в соответствии.
- **Округление вверх идёт через `EPS = 1e-9`**: в float `0.1 × 30 = 3.0000000000000004`, и голый `Math.ceil` даёт 4 вместо 3. Тест `test_float_rounding` охраняет это поведение.
- **Битые строки исключаются из расчёта и показываются отдельным списком** с номером строки и причиной — решение пользователя. Весь файл отклоняется только при пустом файле или отсутствующих столбцах. CLI завершается с кодом 1, если были ошибки.
- **Валидация живёт в двух местах** (JS и Python) и должна совпадать: новое правило добавляй в оба, плюс строку в `data/invalid.csv`.
- Отчёт CSV пишется с `;` и BOM — так его корректно открывает Excel в русской локали.
- Папка `исходные данные/` (документ ТЗ работодателя) в `.gitignore` намеренно — в публичный репозиторий её не выкладываем.

## Окружение (Windows)

- Тесты на stdlib `unittest` (pytest не установлен): `npm test`. В Git Bash ставь `PYTHONIOENCODING=utf-8`, иначе кириллица в выводе падает с `UnicodeEncodeError`.
- Git-автор в репозитории не настроен — перед первым коммитом уточни у пользователя имя.

## Готово, когда

`npm test` зелёный, `npm run build` проходит, а пример вывода в `README.md` совпадает с реальным `npm run calc`.
